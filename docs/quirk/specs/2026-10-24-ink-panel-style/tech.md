## Contracts & interfaces

### Extra rule shape

Back-link: [Conceptual model](logic.md#conceptual-model), [SC-13](logic.md#behavior--scenarios).

`SCHEMA:` an `extra_css` entry has `selector`, `mode` and `declarations`, and may have `media`, one of
`"hover"` or `"forced-colors"`. Any other key is a `StyleError`. An entry without `media` that uses no
motion property renders exactly as today, which is what keeps the seven existing outputs byte-identical
(SC-12).

`CONTRACT:` selector grammar, extending `SELECTOR_RE`:

- The selector must contain `[data-mini=` or `[data-slot=` (today: `[data-mini=` only). The error
  message names both.
- `:active` joins the allowed pseudo-classes. Commas, backslashes, `:not()` and every other
  pseudo-class stay rejected.
- The press marker is the attribute `data-mini-pressed` (no value), so `[data-mini-pressed]` already
  matches `_ATTR`.

`CONTRACT:` new allowed properties and their value grammars. Each value still passes
`FORBIDDEN_VALUE_FRAGMENTS`, the quote ban and the backslash ban.

| Property | Allowed value |
|---|---|
| `border-width`, `outline-width`, `outline-offset` | one length (`LENGTH_RE`), or for `outline-offset` a negative length too |
| `border-style`, `outline-style` | `solid` or `none` |
| `transform` | `none`, or `translate(<x>, <y>)` where each is `0` or a `px` length with absolute value at most `8px` |
| `transition` | `none`, or one to four comma-separated items `<property> <time>[ <easing>]`; property one of `transform`, `box-shadow`, `background-color`, `border-color`, `color`, `opacity`; time `0s`, or ms/s up to `200ms`; easing one of `ease`, `ease-in`, `ease-out`, `ease-in-out`, `linear` |
| `transition-duration` | one time, `0s` up to `200ms` |
| `translate` | `none` only |

Any other value for these properties is a `StyleError` naming the source, the rule index, the property
and the reason (for example `transition: all 2s` → "must name what it moves"; `transition: transform
2s` → "at most 200ms"; `transform: scale(2)` → "may only translate"; `translate: 1px` → "may only be none").
`MOTION_PROPERTIES = {"transform", "transition", "transition-duration"}`.

`CONTRACT:` a motion declaration is motion-free when its value removes motion: `transform: none`,
`transition: none`, or a zero `transition-duration` (`0s`, `0ms`). `translate: none` is always
motion-free, so `translate` is allowed but is not in `MOTION_PROPERTIES`. A rule is a motion rule only
when at least one of its motion declarations is not motion-free.

### Rendering

Back-link: [Data flow](logic.md#data-flow), [SC-8, SC-9, SC-10](logic.md#behavior--scenarios).

`CONTRACT:` `_rule` keeps its output for a plain entry. A wrapped entry renders as

```
@media <query> {
  <prefix><selector> { <declarations> }
}
```

where `<query>` is, in this order of precedence:

| Entry | Query |
|---|---|
| motion property and `:hover` in the selector | `(hover: hover) and (prefers-reduced-motion: no-preference)` |
| motion property (with or without `media: "hover"`) | `(prefers-reduced-motion: no-preference)`, combined with `(hover: hover)` when `media` is `"hover"` |
| `media: "hover"`, no motion | `(hover: hover)` |
| `media: "forced-colors"`, no motion | `(forced-colors: active)` |

A motion-free declaration does not count as a motion property in this table: a rule whose motion
declarations are all motion-free is not wrapped in the reduced-motion query and renders as a plain rule,
or under its own `media` query. That keeps `transition: none` in force under reduced motion, where
shadcn's `transition-all` would otherwise apply (SC-8). A motion property together with `media:
"forced-colors"` is a `StyleError`; a motion-free one is not. The mode prefix
(`html:not(.dark) `, `html.dark `, or the gallery's `html[data-mini-style="<slug>"]…`) goes inside the
media block, on the selector, exactly as for an unwrapped entry. Each wrapped entry gets its own media
block, in source order, so rule order is preserved.

`parse_extra_css` must keep returning the inner rules of media-wrapped blocks (its `BLOCK_RE` already
finds the innermost `selector { … }`); add a test that proves it for a wrapped `data-mini` rule.

### Press marker

Back-link: [SC-6, SC-7, SC-9](logic.md#behavior--scenarios).

`CONTRACT:` `gallery/src/lib/mini/press.ts` is a side-effect module with no exports, guarded so a second
import does nothing (a flag on `window`). It installs capture-phase listeners on `document`:

- `pointerdown` (primary button only): find `target.closest('[data-slot="button"], [data-slot="toggle"],
  [data-slot="toggle-group-item"]')`; skip when none, or when it is `:disabled` or
  `aria-disabled="true"`. Set `data-mini-pressed` on it and record the time.
- `pointerup`, `pointercancel`: release the pressed element.
- `keydown` of `" "` or `"Enter"` without `repeat`, when `document.activeElement` matches the same
  selector: press it. `keyup` of the same key, and `blur` (capture): release.
- Release removes the attribute after `max(0, 120 - elapsed)` ms, so a press shows for at least 120ms.
  A new press of the same element cancels a pending removal.

It never calls `preventDefault`, `stopPropagation` or `click()`, and never delays an event. It writes
only the `data-mini-pressed` attribute.

`CONTRACT:` `_mini.press_step(app) -> int`, run by `new_app.py` and `set_style.py` right after
`tokens_step`:

- Copies `gallery/src/lib/mini/press.ts` to `<app>/src/lib/mini/press.ts` when that file is absent;
  never overwrites an existing one.
- Adds `import "./lib/mini/press"` to `<app>/src/main.tsx` once, as the first line of the
  file; detection ignores comments, template literals and strings. Idempotent: a file that
  already has the import is not rewritten.
- A missing `src/main.tsx` is `step_failed("press", …)` (exit 1).
- Prints `+ [press] …` like the other steps.

`gallery/src/main.tsx` imports `./lib/mini/press` after `./index.css`. `set_style.py`'s docstring names
the press marker beside the font lines as what it may add.

### Ink Panel source

Back-link: [Conceptual model](logic.md#conceptual-model), [Decisions Locked](logic.md#decisions-locked).

`CONFIG:` `slug` `ink-panel`, `name` `Ink Panel`, `studied_from` `["sentry"]`, `radius` `0.375rem`
(6px), `fonts.sans` and `fonts.heading` `'Space Grotesk Variable', system-ui, sans-serif`, `fonts.data`
the system monospace stack the other styles use, `font_packages`
`["@fontsource-variable/space-grotesk"]`.

Tokens, both modes, re-derived in oklch from the logic spec's approximate hex values so every
`CONTRAST_PAIRS` pair clears its minimum:

| Role | Token(s) | Light | Dark |
|---|---|---|---|
| page | `background` | paper ≈ #fbf6ea | night ≈ #1c1824 |
| ink, text | `foreground`, `card-foreground`, `popover-foreground`, `accent-foreground` | ≈ #1b1722 | cream ≈ #ece4d2 |
| surfaces | `card`, `popover` | ≈ #fffdf7 | ≈ #26212f |
| primary | `primary`, `ring`, `sidebar-primary`, `sidebar-ring` | cobalt ≈ #2357d9 | ≈ #7da2ff |
| selection, menu hover | `accent`, `sidebar-accent` | marker yellow ≈ #ffe682 | deep amber ≈ #4d3d0a |
| muted text | `muted-foreground` | ≈ #5b5466 | ≈ #b3aabf |
| dividers | `border`, `sidebar-border`, `input` | ≈ #ddd5c4 | ≈ #3a3445 |
| sidebar | `sidebar` | ≈ #f4eddc | ≈ #221d2b |

The rest (`secondary`, `muted`, `destructive`, `chart-*`, `mini-*`) follow the palette and the gate.

`CONTRACT:` Ink Panel's `extra_css`, using `var(--foreground)` as ink and `var(--primary)` as cobalt:

- **Controls** (`button` with `data-variant` `default`, `outline`, `secondary`, `destructive`; `input`;
  `textarea`; `select-trigger`; `toggle`; `toggle-group-item`): `border-width: 2px`, `border-style:
  solid`, `border-color: var(--foreground)`, `border-radius: 6px`, `box-shadow: 3px 3px 0
  var(--foreground)`. `ghost` and `link` buttons get none of this and no motion. Inputs get no motion.
- **Chips** (`badge`): 2px ink border, 6px radius, no offset shadow. `data-variant="default"` uses the
  marker-yellow chip fill (≈ #ffd84d, as an oklch literal) with ink-black text in both modes.
- **Panels** (`card`, `dropdown-menu-content`, `context-menu-content`, `popover-content`,
  `select-content`, `dialog-content`, `[data-mini="panel"]`, `[data-mini="surface"]`): 2px ink border,
  8px radius, `box-shadow: 5px 5px 0 var(--foreground)`.
- **Selected row** (one entry per selection state): `background-color: var(--accent)`, `color:
  var(--accent-foreground)`, `box-shadow: inset 0 0 0 2px var(--foreground), 4px 4px 0 var(--primary)`.
  Rows otherwise keep their 1px dividers.
- **Focus** (`:focus-visible` on each control slot): `outline-width: 2px`, `outline-style: solid`,
  `outline-color: var(--ring)`, `outline-offset: 3px`, keeping the control's offset shadow.
- **Motion** (the four button variants, `toggle`, `toggle-group-item`): base `transition: transform
  120ms ease-out, box-shadow 120ms ease-out`; `:hover` `transform: translate(-1px, -1px)`, `box-shadow:
  4px 4px 0 var(--foreground)`; `[data-mini-pressed]` `transform: translate(3px, 3px)`, `box-shadow:
  none`, `transition-duration: 0s`. The base outline and shadow rule of each of these controls also sets
  `translate: none` and `transition: none` as motion-free declarations. `translate: none` cancels
  shadcn's `active:translate-y-px`, which Tailwind compiles to the `translate` property, so the press
  nudge does not stack; `transition: none` cancels shadcn's `transition-all` under reduced motion. Both
  win because the tokens file is unlayered. These base rules come before the wrapped `transition` rule,
  so with no preference the wrapped `transition` wins at equal specificity by source order.
- **Non-motion hover and press** (so SC-8 still reads): a `media: "hover"` rule growing the shadow to
  4px, and a plain `[data-mini-pressed]` rule removing the shadow.
- **High contrast** (`media: "forced-colors"`): each selected-row state gets `outline-width: 2px`,
  `outline-style: solid`, `outline-color: Highlight`, `outline-offset: -2px`. Borders survive forced
  colors on their own, so controls and panels need no fallback.

## DO-NOT-CHANGE fences

- **The seven existing styles' sources and outputs.** `styles/dist/<slug>.css` for the seven, and their
  blocks in `gallery-styles.css`, stay byte-identical. Why: SC-12.
- **`gallery/src/components/ui/**` and `gallery/src/patterns/**`.** Ink Panel reaches components
  through existing `data-slot` and `data-mini` hooks only. Why: blocks just passed review; a style never
  changes structure.
- **Generated files by hand**: regenerate with `build_styles.py` and `build_registry.py`.
- **`FORBIDDEN_VALUE_FRAGMENTS`, the quote and backslash bans.** Unchanged. Why: the `url()`
  exfiltration path ([Industry Insights](logic.md#industry-insights)).

## Always / Ask / Never

- **Always**: stdlib-only Python; deterministic output; rerun `build_styles.py` and
  `build_registry.py --check` after any source or gallery change.
- **Ask** (NEEDS_CONTEXT): any npm dependency other than `@fontsource-variable/space-grotesk`; any
  edit under `components/ui/` or `patterns/`.
- **Never**: write "Sentry" into the style's `name`, generated CSS, `style-list.json` or anything an
  app receives; let a style ship JavaScript.

## Testing strategy

- `tests/test_building_mini_apps_styles.py` (no subprocess, no network):
  - each new value grammar accepts its good forms and rejects the SC-13 cases plus `transform:
    rotate(1deg)`, `translate(9px, 0)`, `transition: transform 201ms`, `transition: all 100ms`,
    `border-style: dashed`; the `media` key accepts `hover` and `forced-colors` and rejects others; an
    unknown rule key is rejected; motion with `forced-colors` is rejected.
  - a `[data-slot="button"]` selector and `:active` are accepted; `:not(`, `:focus` and commas are not.
  - rendering: a motion rule, a motion `:hover` rule, a `media: "hover"` rule and a `forced-colors`
    rule each render in the right `@media` block with the mode prefix inside, in app and gallery CSS.
  - `parse_extra_css` returns a media-wrapped `data-mini` rule.
  - the seven existing dist files are unchanged by the new renderer (compare with the committed bytes).
  - eight sources; `style-list.json` lists the eight; `Sentry` joins `APP_DISPLAY_NAMES`.
- `tests/test_building_mini_apps_set_style.py`: `press_step` copies the file when absent and leaves an
  existing one alone; adds the import once as the first line; is idempotent; fails without
  `src/main.tsx`; `new_app.py` and `set_style.py` run it after `tokens`. Rename the `_seven` test names.
- `tests/test_building_mini_apps_skill.py`: `check_docs.py style ink-panel` passes.
- Gallery: `pnpm build` and `pnpm exec eslint src` clean.

`COMMAND:` the per-wave gate, from the repo root:

```
COMMAND: python3 -m pytest -q tests/test_building_mini_apps_skill.py tests/test_building_mini_apps_styles.py tests/test_building_mini_apps_set_style.py && python3 skills/building-mini-apps/scripts/build_registry.py --check && python3 skills/building-mini-apps/scripts/build_styles.py --check && (cd skills/building-mini-apps/gallery && pnpm build && pnpm exec eslint src)
```

After the last wave, the orchestrator runs the gallery pass: Ink Panel on every gallery pattern page, light
and dark, screenshots to `references/media/styles/ink-panel/<pattern>-<mode>.png` (gitignored), plus a
rendered-contrast probe that reads computed colors of text on the selected row, chips, primary
buttons and menu hover in both modes and checks 4.5:1. It also checks the press marker in a browser:
a 10ms press and release keeps `data-mini-pressed` for about 120ms, with reduced motion emulated and without.
