### `attention.ts` (pure)

```ts
CONTRACT: function itemStatus(item: AttentionItem, now: number): ItemStatus
CONTRACT: function isStale(tile: Tile, now: number): boolean
CONTRACT: function evaluateRules(input: {
  tiles: Tile[]; items: AttentionItem[]; rules: FlagRule[];
  previous: RuleMemory; now: number; newId: () => string
}): { add: AttentionItem[]; append: Array<{ id: string; events: TimelineEvent[] }>; memory: RuleMemory }
CONTRACT: function applyItemAction(item: AttentionItem, action: ItemAction, now: number): TimelineEvent[]
CONTRACT: function endExpiredSnoozes(items: AttentionItem[], now: number): Array<{ id: string; events: TimelineEvent[] }>
CONTRACT: function initialRuleMemory(items: AttentionItem[], rules: FlagRule[], tiles: Tile[]): RuleMemory
CONTRACT: function stateText(tile: Tile): string
CONTRACT: function snoozePresets(now: number): Array<{ label: string; until: number }>
```

- **`itemStatus`** folds the timeline: the last of `opened | reopened | acknowledged | snoozed |
  resolved | cleared` decides. `cleared` and `resolved` give `resolved`; `snoozed` gives
  `snoozed` while `until > now`, otherwise the status before the snooze is ignored and the result
  is `open`; `acknowledged` gives `acknowledged`; `opened` / `reopened` give `open`.
  `flagged-again` and `snooze-ended` never change status on their own except that `snooze-ended`
  makes the item `open`. Status is never stored.
- **A flag is an edge, not a level.** `evaluateRules` fires a rule only when its condition goes
  from false to true, or when the condition stays true and the rule's `occurrence(tile)` key
  changes. `RuleMemory` holds the last condition value and occurrence key per rule; it lives in
  the hook, not in the store. On mount, `initialRuleMemory` treats a rule as already true when the
  rule's latest item is not resolved, or was resolved by hand (last event `resolved`) rather than
  by `cleared`; so a reload never re-flags something the user dismissed while it was still true.
- **On a fire** for a tile rule: the rule's latest item is (a) not resolved → append
  `flagged-again`; (b) resolved by any means less than 24 h ago (`now - resolvedAt < 86_400_000`)
  → append `reopened`; (c) otherwise, or no item → `add` a new item with `opened`.
- **On a condition going true → false** with a non-resolved item: append `cleared` with text
  `Cleared: <tile name> <state text>`.
- **Staleness opt-in** (`tile.staleOpensItem`) is evaluated as a synthetic rule per tile with
  id `stale:<tileId>`, urgency `later`, title `<tile name> has not reported`, condition
  `isStale(tile, now)`.
- **`applyItemAction`** returns the events to append: `acknowledge` (only from `open`), `snooze`
  (from `open` or `acknowledged`; `until > now` required, optional `note`), `resolve` (from any
  non-resolved status). An action not allowed from the current status returns `[]`.
- **`endExpiredSnoozes`** appends one `snooze-ended` (at the snooze's `until`) to each item whose
  status was snoozed and whose `until <= now`, exactly once per snooze.
- **`snoozePresets`**: 1 hour; This evening (18:00 today, omitted if `now` is past 17:00); Tomorrow
  morning (08:00 next day); Next week (08:00 next Monday). "Pick a date" is a UI affordance that
  produces 08:00 on the chosen date.
- **Every lifecycle function returns only the events to append, never a whole timeline.** The
  hook is the one place that concatenates: it writes `onItemUpdate(id, { timeline: [...item.timeline, ...events] })`
  from the item it currently holds. `useCollection.update` shallow-merges the patch, so passing
  only the new events would erase the history.
- **`initialRuleMemory`** keys off `item.ruleId`, including synthetic `stale:<tileId>` ids, which it
  derives from `tiles` with `staleOpensItem`, so a reload treats a hand-resolved stale item the
  same as any other rule.
- **`stateText`** is the single source of a tile's state words: `toggle` gives `onLabel ?? "On"` or
  `offLabel ?? "Off"`; `level` gives `<value><unit>` when on, otherwise `offLabel ?? "Off"`;
  `target` gives `<value><unit> · target <target><unit>`; `sensor` gives `text ?? "<value><unit>"`.
  The tile, the dialog, the `cleared` text (`Cleared: <name> <stateText>`, lower-cased state) and
  the confirm copy (`<onVerb|offVerb> <name>?`) all use it.
- No function throws on unknown ids; unknown tiles in a rule are skipped.

### `use-command-center.ts`

```ts
CONTRACT: function useCommandCenter(opts: {
  tiles: Tile[]; items: AttentionItem[]; rules: FlagRule[];
  onTileUpdate: (id: string, patch: Partial<Tile>) => Promise<void>;
  onItemAdd: (item: AttentionItem) => Promise<void>;
  onItemUpdate: (id: string, patch: Pick<AttentionItem, "timeline">) => Promise<void>;
  onRefresh?: (signal: AbortSignal) => Promise<Array<Pick<Tile, "id"> & Partial<Tile>>>;
  refreshMs?: number;
}): {
  now: number; announcement: string;
  refresh: RefreshState; pause(): void; resume(): void; retry(): void;
  act(itemId: string, action: ItemAction): void;
}
```

- Runs `evaluateRules` whenever `tiles` (by `updatedAt` or state) or `rules` change, and on each
  tick (for staleness). Writes go through the callbacks; a rejected write shows `toast.error` and
  leaves the store's last good items (the store already guarantees that). `RuleMemory` advances
  per rule: a rule whose write resolved (or that had none) takes its new memory, while a rule whose
  write rejected keeps its old memory so the next evaluation fires the same edge again. A sibling
  rule's failure therefore neither replays an already-stored edge nor loses a later clear.
- **`updatedAt` is stamped by the hook**: a toggle, level or target change from the UI is written as
  `onTileUpdate(id, { ...patch, updatedAt: now })`; a refresh patch without `updatedAt` gets
  `updatedAt: now` added. Toggling a `toggle` or `level` tile patches `{ on: !tile.on }`.
- Tick: one `setInterval` of 30 s (tighter than the logic spec's "about once a minute", so a snooze
  returns within half a minute) plus an immediate tick on `visibilitychange` to visible. Each
  tick sets `now`, runs `endExpiredSnoozes`, and sets `announcement` to `<title> is back` for each
  returned item.
- Refresh: when `onRefresh` is given, call it at mount and every `refreshMs` (default 30 000)
  unless paused; abort the in-flight call on unmount or pause. Success writes each returned patch
  via `onTileUpdate` and sets `{ state: "live", at: now }`. Failure keeps tiles untouched and sets
  `{ state: "stale", since: <last success>, error }`. `retry()` runs one refresh now; while one
  is in flight it does nothing. Pausing after a failure gives `{ state: "paused", at: <last success> }`
  and hides the error banner; resuming refreshes at once.
  Without `onRefresh`, `refresh` is `{ state: "none" }`.
- Never runs two refreshes at once.

### `CommandCenter` and parts

```ts
CONTRACT: function CommandCenter(props: CommandCenterProps): JSX.Element
CONTRACT: type CommandCenterProps = Parameters<typeof useCommandCenter>[0] & {
  sourceLabel: string; loadedAt?: number;
  summaries?: Array<{ id: string; label: string; tileId?: string }>;
  status?: "loading" | "ready" | "error"; error?: Error; onRetry?: () => void;
}
CONTRACT: function BadgeRow(props: { summaries: NonNullable<CommandCenterProps["summaries"]>; needYouCount: number; onFocusQueue(): void; onOpenTile(id: string): void })
CONTRACT: function TileBoard(props: { tiles: Tile[]; items: AttentionItem[]; now: number; onToggle(tile: Tile): void; onOpen(tile: Tile, trigger: HTMLElement): void; onLevel(tile: Tile, value: number): void; onTarget(tile: Tile, target: number): void })
CONTRACT: function TileDialog(props: { tile: Tile | null; item: AttentionItem | null; now: number; returnFocusRef: React.RefObject<HTMLElement | null>; onOpenChange(open: boolean): void; onToggle(tile: Tile): void; onAct(action: ItemAction): void })
CONTRACT: function AttentionQueue(props: { items: AttentionItem[]; tiles: Tile[]; now: number; onAct(itemId: string, action: ItemAction): void; onOpenTile(id: string): void })
```

- Every part works rendered alone with only its props. No context provider exists in the block.
- `TileBoard`: sections in the order of first appearance in `tiles`. Each tile renders two real
  buttons: the icon button (only for `kind !== "sensor"`) with a constant `aria-label` of the
  action (`Toggle <name>`) and `aria-pressed`; and the body button that opens details. A tile with
  `sensitive: true` routes the toggle through `confirm-dialog.tsx` first. A tile with an active
  item shows the attention style: `bg-(--mini-pending)` tint plus an icon and text, never colour
  alone. A stale tile dims its value and shows "Stale" with an icon and `Updated <age> ago`.
  Numeric tiles with `history` show a sparkline (`aria-hidden`; the value is in text).
- `TileDialog`: `Dialog` from `@/components/ui/dialog`. Shows controls, the exact last-update time,
  a larger history chart (`role="img"` with an `aria-label` naming latest, min and max), then, when
  `item` is set, the same actions and timeline as the queue. Esc closes and returns focus to the
  tile body button that opened it (`returnFocusRef`, as `confirm-dialog.tsx` also takes, following
  `G/patterns/view-switcher/confirm-dialog.tsx:14-31`).
- `AttentionQueue`: groups non-resolved, non-snoozed items into Now then Later, newest first
  within each group. One item is expanded at a time (actions, timeline, tile link). Hotkeys,
  scoped to the queue root and disabled while focus is in a form field or a dialog or menu is
  open: `j` / `k` move the selection, `a` acknowledge, `s` open the snooze menu, `r` resolve,
  Enter toggles expansion. Empty: "Nothing needs you".
- `CommandCenter` layout: header (source label, `loadedAt`, refresh state, pause/resume),
  `BadgeRow`, then a row of `TileBoard` and the queue column. Below a 768 px container width
  (`@container` query on the block root), the queue becomes a collapsible
  `<n> need you` strip above the tiles (a `collapsible`), and tiles flow in one column. The count
  badge is hidden when the count is 0. With no tiles, `EmptyState` with title "No tiles yet".
  A refresh failure shows an inline alert with Retry above the tiles; tiles keep their last values.
  The hidden announcer (`role="status" aria-live="polite" className="sr-only"`) renders on mount.
- Tile keyboard: plain Tab order through each tile's buttons, section by section (our design;
  no roving focus in the grid).

## Data models / schemas

Back-links: [Conceptual model](logic.md#conceptual-model), [Glossary](logic.md#glossary).

```ts
SCHEMA: type Tile = {
  id: string; section: string; name: string;
  kind: "toggle" | "level" | "target" | "sensor";
  on?: boolean; value?: number; unit?: string; target?: number; text?: string;
  onLabel?: string; offLabel?: string; onVerb?: string; offVerb?: string;
  sensitive?: boolean; updatedAt: number;
  staleAfterMs?: number; staleOpensItem?: boolean;
  history?: number[];
}
SCHEMA: type FlagRule = {
  id: string; tileId: string; title: string; urgency: Urgency;
  test: (tile: Tile) => boolean;
  occurrence?: (tile: Tile) => string;
}
SCHEMA: type Urgency = "now" | "later"
SCHEMA: type AttentionItem = {
  v: 1; id: string; title: string; urgency: Urgency;
  tileId?: string; ruleId?: string; timeline: TimelineEvent[];
}
SCHEMA: type TimelineEvent = {
  at: number;
  type: "opened" | "flagged-again" | "acknowledged" | "snoozed" | "snooze-ended" | "cleared" | "resolved" | "reopened";
  until?: number; note?: string; text?: string;
}
SCHEMA: type ItemStatus = "open" | "acknowledged" | "snoozed" | "resolved"
SCHEMA: type ItemAction = { type: "acknowledge" } | { type: "snooze"; until: number; note?: string } | { type: "resolve" }
SCHEMA: type RefreshState = { state: "none" } | { state: "live"; at: number } | { state: "paused"; at?: number } | { state: "stale"; since?: number; error: Error }
SCHEMA: type RuleMemory = Record<string, { on: boolean; occurrence?: string }>
```

- `FlagRule` holds functions, so rules are a prop, never stored. Tiles and items are stored
  (`useCollection<Tile>("command-center-tiles", seed)`, `useCollection<AttentionItem>("command-center-items", seed)` in the demo).
- `AttentionItem.v` is the timeline format version (resolves the logic spec's deferred
  `[tech-spec]` question). Readers treat a missing `v` as 1.
- Times are epoch milliseconds.

## Cross-cutting

- **Security**: the refresh function is the app's code; the block never stores credentials or
  URLs. No network calls in the demo.
- **Data migration**: `AttentionItem.v = 1` from the start; no migration needed.
- **Performance**: rule evaluation is O(rules + items) per change; fine for the tens of tiles this
  pattern targets.
- **Accessibility**: real buttons only; `aria-pressed` with constant labels on toggles; one
  polite announcer; the refresh error banner uses `role="alert"`; dialog focus returns to its
  trigger.
