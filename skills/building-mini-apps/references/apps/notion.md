## Observations

- S4, `references/media/notion/S4-views-filters-sorts.png`: the help text says "you can view the same database in multiple ways, and switch back and forth", that new databases start as a table, and that a view is added with "+" next to the database name or the existing tabs. On narrow screens the current view name opens a menu with "New view". → feeds: view-switcher
- S4, `references/media/notion/S4-group158.png`: the view tab strip sits directly under the page title and left-aligned, with the toolbar right-aligned on the same row. Tabs are icon plus name ("Table", "Calendar", "Chart"); the selected tab is a light gray pill, not an underline. Toolbar order, left to right: filter, sort, automations (lightning), search, settings (sliders), then a blue "New" button with a split chevron. → feeds: view-switcher
- S4, `references/media/notion/S4-layouts.png`: the "..." settings button opens a Layout panel docked on the right (about 30% of the frame width) while the table stays visible and interactive on the left. The panel has a back arrow, the title "Layout", a close X, a 3x2 grid of layout tiles (Table, Board, Timeline / Calendar, List, Gallery) with the active tile outlined in blue, a one-line description of the active layout, and toggles ("Show vertical lines", "Wrap all columns", "Show page icon") plus an "Open pages in: Side peek" row. → feeds: view-switcher, inspector
- S4, page text: each view keeps its own settings (layout, property visibility, filter, sort, group, sub-group); changing one does not change the others. Clicking the active tab's name opens rename, duplicate, delete, copy link to view and edit view. Tabs can be reordered by dragging, and overflow collapses into "N more..." in the strip. → feeds: view-switcher
- S4, page text: a tab can show icon only, text only, or both ("Display as"), and that choice is per person and per database. In the sidebar, views appear as nested items under a full-page database, marked with a bullet. → feeds: view-switcher, workspace-panes
- S4, page text: filters and sorts have a "Save for everyone" option; without it the filter or sort applies only to the person who set it. Filters can be nested up to three AND/OR groups ("advanced filter"). Multiple sorts reorder by dragging the handle. Select-type properties sort by the order of their options, not alphabetically. → feeds: view-switcher, staged-table-edit
- S4, page text: "Open pages in" is set per view with three values: Side peek (page opens on the right while the view stays interactive), Center peek (centered modal), Full page. Table, Board, List and Timeline default to side peek; Gallery and Calendar default to center peek. → feeds: view-switcher, list-peek, inspector
- S4, page text: database search appears only when the database has at least three pages and matches page titles and properties as you type. One column can be frozen so it stays visible while scrolling horizontally. → feeds: view-switcher, staged-table-edit

## Unseen

- Side peek: no frame in any source shows a page open in side peek; only the help text (S4) and the "Open pages in: Side peek" row (S4-layouts) show it exists and is the default for table, board, list and timeline.
- The filter and sort popovers themselves (property picker, operator dropdown, value field, "Save for everyone" toggle) were never on screen; only the resulting chips (S2-0015) and help text.
- Keyboard shortcuts: none appear on screen in any frame, and none of the sources demonstrate keyboard navigation between view tabs or in a peek.
- How switching tabs animates, and whether scroll position or selection survives a switch; no frame sequence shows it.
- The "N more..." overflow menu contents and drag-to-reorder of tabs.
- Error states (failed load, permission denied, broken filter) and any skeleton loader; only a blank white peek (S1-0014) was seen.
- Changing "Open pages in" for a view and seeing the effect immediately.
- Narrow-window behavior where the strip collapses to a single view-name menu (described in S4 text, not shown).
- Whether the selected view is remembered after a reload.

## Patterns fed

- view-switcher: the core contribution. A tab strip under the title with one tab per view over the same records, icon plus name, active tab as a pill, a trailing "+" with a tooltip that opens a grid of layout types, per-view settings in a right-docked panel, per-view filter and sort with a colored toolbar icon when active, and a count of records a layout cannot show.
- list-peek: the "OPEN" pill and gutter handles on row hover, and opening a record in a center peek about 58 to 82% of the window width over a dim scrim, with expand, Share, star and "..." in the peek header.
- inspector: the peek page as a property list (label left, value right, gray "Empty") above comments, and the per-view "Open pages in" choice of side peek, center peek or full page.
- expand-in-place: the expand control at the top-left of a peek that promotes it to a full page.
- doc-collections: databases whose rows are pages, nested databases with their own view tabs inside a peek, and sources added as views.
- staged-table-edit: the table layout (type icons in headers, row hover gutter, count footer, "+ New" row, frozen first column) and sorts or filters as chips that stay attached to a view.
- workspace-panes: views listed as nested sidebar items under a full-page database.
